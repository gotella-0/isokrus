# Как устроен конвейер

Программа получает PDF с изометрическими чертежами и возвращает таблицу длин
трасс с формулами и разметку листов. Ключевое решение: **геометрию программа
берёт из векторного слоя PDF, а не от модели**. Vision-LLM отвечает только
на один вопрос — какие из найденных размеров входят в длину трассы. Сумму
считает программа.

```
PDF ──► dimscan.py ──► размеры (вектор, пункты)      ──► {{DIMENSIONS}} в промт
  │        └──► отсеянные числа («не размер»)        ──► тот же блок
  │        └──► prune+redact: вырез шума из PDF      ──► до рендера
  ▼
рендер ──► trim.py ──► PageImage (байты PNG в памяти)
  │                       │
  │                       ├──► textmap.py: подписи текстового слоя
  │                       │                       ──► {{PDF_TEXT}} в промт
  │                       ├──► base64 ──► llm.py ──► vision-LLM (strict JSON)
  │                       │                            ▲
  │                       │                research/exp_13/system.md
  │                       │                {{DIMENSIONS}} + схема ответа
  │                       └──► output/exp_13/pages/*.png  (те же байты)
  ▼
indices.py ──► метки → длины ──► сумма программой ──► report.py (CSV/XLSX)
                                 └──► annotate.py ──► разметка листов
```

Порядок шагов на лист зафиксирован и не переставляется:
**разбор размеров → зачистка вырезом → рендер → обрезка полей → текстовый слой → подсветка**.
Разбор идёт до рендера, потому что работает с вектором в пунктах; зачистка
вырезает подписи из содержимого страницы, поэтому её результат уже сидит
в отрендеренном растре и в текстовом слое. Рамки размеров и подписи
пересчитываются в пиксели **обрезанной** картинки одной матрицей — промт,
разметка и картинка смотрят на одну систему координат.

## Шаги конвейера

1. **Разбор размеров** (`dimscan.py`). По вектору PDF, до рендера: собираются
   числа листа, отсеиваются те, что размером не являются (позиционные знаки
   в квадратах, координаты привязки `X/Y/Z+`, марки труб, штамп), к каждому
   оставшемуся ищется ближайшая стрелка или отрезок. Пороги заданы для
   эталонного листа и сами пересчитываются под масштаб каждой страницы по
   кеглю подписей — поэтому новый PDF обрабатывается без правки кода.
2. **Зачистка** (`prune.py` + `redact.py`). Элементы, которые разбор и
   регулярка признали не-размерами, вырезаются из содержимого страницы
   (`add_redact_annot` + `apply_redactions`): в рендере не остаётся ни
   серого ореола, ни обрезка буквы, а подписи исчезают и из текстового слоя.
   Размер не трогается никогда: прямоугольник, задевающий подпись размера
   или его линию, не применяется вовсе, а попадает в отчёт.
3. **Рендер и обрезка полей** (`extract.py`, `trim.py`). Страницы рендерятся
   в память, пустые поля срезаются по факту нарисованного: на этом комплекте
   это 32–59 % площади листа, то есть примерно на четверть больше пикселей
   на миллиметр чертежа. На диск до конца обработки ничего не пишется.
4. **Текстовый слой** (`textmap.py`). Подписи, нарисованные шрифтом,
   извлекаются той же матрицей, что и картинка: их положение известно точно,
   модель его оценивала на глаз и промахивалась.
5. **LLM** (`llm.py`, `usage.py`). OpenAI-совместимый API, ответ всегда
   strict `json_schema` — контракт «что проверяем» и «что требуем» один.
   Режим размышления передаётся в форме, которую ожидает конкретная модель.
   Повторы: сетевой сбой — тот же запрос 1-в-1; невалидный JSON — повтор
   с возвратом модели её ответа и текста ошибки. Токены и стоимость
   считаются с учётом кеша и рассуждений (`usage.py`).
6. **Суммирование** (`indices.py`, `report.py`). Модель отвечает метками
   `included`/`excluded`, метки разворачиваются в длины программно: модель
   физически не может назвать число, которого нет на листе. Сумма складывается
   программой, расхождение с заявленной моделью помечается в отчёте.
7. **Разметка** (`annotate.py`). Числа, названные моделью, сопоставляются
   с подписями листа и обводятся по их настоящим рамкам: что вошло в расчёт
   и что исключено видно на чертеже.

## Карта модулей

### Конвейер — то, что реально работает

| Модуль | Ответственность |
|---|---|
| `cli.py` | Разбор аргументов, команды `run`/`analyze`/`extract`/`text`/`dims`/`experiments`/`schema`/`prompt` |
| `pipeline.py` | Оркестрация прогона: пул потоков, сбор результатов, JSON-отчёт |
| `extract.py` | Извлечение страниц: порядок шагов, `PageImage` в памяти |
| `dimscan.py` | Разбор вектора: числа, отсеянные числа, размерные линии, масштаб |
| `prune.py` | План зачистки: какие элементы вырезать, какие рамки растут до знака |
| `redact.py` | Вырезание из PDF с защитой размеров (guard) |
| `trim.py` | Обрезка пустых полей по пикселям |
| `textmap.py` | Текстовый слой: подписи в пикселях, блок `{{PDF_TEXT}}` |
| `overlay.py` | Подсветка размеров и метки `P7` на картинке (опционально, по замерам выключена) |
| `clean.py` *(удалён в ветке remove-dead-code)* | Растровая зачистка, заменена вырезом из PDF |
| `classify.py` | Роли текстовых элементов: координата, знак, штамп, размер |
| `llm.py` | Вызов API: strict JSON, повторы, repair-раунды |
| `usage.py` | Учёт токенов и стоимости, разбор `usage` провайдера |
| `experiments.py` | Загрузка промта и схемы из `research/exp_NN/`, токены блоков |
| `schema.py` | JSON Schema → pydantic-модель, strict-конвертация |
| `indices.py` | Метки `included`/`excluded` → длины, сумма |
| `report.py` | CSV/XLSX/статистика |
| `annotate.py` | Разметка листов: рамки чисел по текстовому слою |
| `config.py` | Все параметры из окружения |
| `errors.py` | Иерархия исключений |

### Что где лежит

```
research/          эксперименты: exp_01…exp_17, в каждом промт+схема+meta
reference/         эталон: PNG десяти листов и ручные замеры (list_XX.txt)
tests/             проверки; tests/dimscan/reference.py — поразмерный эталон
output/            артефакты прогонов (не в git): pages, annotated, stats
docs/              эта документация
check_reference.py сверка reference/list_XX.txt с эталоном из кода
```

Проверить конвейер без обращений к API:

```bash
python -m isokrus extract 02_Изометрии_10_листов.pdf --pages 1-10
python -m isokrus dims 02_Изометрии_10_листов.pdf --which 9
python tests/dimscan/__main__.py --check   # сверка разбора с эталоном
```
