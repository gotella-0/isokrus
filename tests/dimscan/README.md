"""Разбор размерных цепочек на листах изометрии (без обращения к LLM).

Запуск из корня проекта:

    python tests/dimscan/__main__.py                 # все варианты, все листы
    python tests/dimscan/__main__.py --pages 1,2     # только два листа
    python tests/dimscan/__main__.py --only ghost    # один вариант
    python tests/dimscan/__main__.py --check         # сверка с эталоном
    python tests/dimscan/__main__.py --dump-json     # + выгрузка отрезков
    python tests/dimscan/probe.py 2 --fills          # что нарисовано на листе
    python tests/dimscan/probe.py 3 --png 13.png --crop 130,240,240,285

Что делает: находит на чертеже размеры и красит каждый в свой цвет, а в
``out/segments.json`` кладёт список со значениями. Всё считается из вектора
PDF, поэтому прогон воспроизводим и не зависит от ключей в ``.env``.

Порядок поиска — **от чисел к геометрии**: сначала собираются числа листа,
потом отсеиваются те, что размером не являются, потом к каждому оставшемуся
ищется ближайшая стрелка или отрезок. Обоснование и список отсева — в
документации ``detect``.

Пороги заданы для эталонного листа (кегль подписи 7.43 pt) и **пересчитываются
под масштаб каждого листа**: множитель берётся из медианного кегля подписей с
цифрами, а толщина размерных линий ищется измерением, а не переносится из
эталона. Поэтому тот же комплект, вписанный в лист в 3 или в 0.25 раза
крупнее/мельче, даёт тот же набор размеров — это проверяется тестом. Множитель
и его источник видны в колонке «масштаб» и в ``segments.json``.

Сверка с эталонными длинами трасс (``--check``) разводит **два независимых
слоя**, потому что зелёный статус одного не должен прикрывать провал другого:

1. **все размеры найдены** — набирается ли эталонная сумма набором найденных
   чисел. Это проверка поиска. На текущем комплекте — «да» на всех 10 листах.
2. **иерархия** — что даёт разбиение на обобщённые и вложенные. Здесь 2 листа
   из 10, и это ожидаемо: **рисунок нарисован не в масштабе** (на листе 5 от
   1.34 до 20.95 мм на пункт), а ряды размеров разных ветвей перекрываются по
   проекции. Родителя из геометрии размерной линии не восстановить — нужна
   топология трассы, она ищется в ``research/exp_04`` по координатам привязки.

Что dimscan делает, так это находит, **какие числа являются размерами, где они
на листе и с чем привязаны** — это нужно и человеку, и модели как проверяемый
список подписей с координатами. Сумму вложенных участков с обобщённым он не
сверяет: она не обязана равняться.

Модули:

``detect``     Числа, отсев «не размер», отрезки и выноски, иерархия.
``layout``     Раскладка имён размеров (P1, P14) по листу без наложений.
``render``     Три варианта подсветки: ``vector``, ``ghost``, ``nodes``.
``reference``  Эталонные суммы листов и проверка достижимости.
``probe``      Дамп текстового слоя и векторной геометрии + вырезка в PNG
               (отладка: «что на самом деле нарисовано в этом углу?»).
"""
