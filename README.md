# isokrus — расчёт длины трубопроводов по изометрическим чертежам

Консольная программа: PDF с изометриями → разбор размеров по вектору →
рендер страниц в память → параллельный анализ каждого листа vision-LLM →
CSV/Excel с длиной трассы, формулой расчёта и разметкой чертежа.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -e .
```

`pip install -e .` обязателен: пакет `isokrus` лежит в `src/` и не публикуется
в PyPI, а `requirements.txt` содержит только сторонние зависимости. Без этой
команды `python -m isokrus` падает с `No module named isokrus`.

После установки доступна и консольная команда `isokrus` — то же самое, что
`python -m isokrus`.

Скопируйте `.env.example` в `.env` и впишите `LLM_API_KEY`.

## Запуск

```bash
# полный цикл по всем листам
python -m isokrus run "02_Изометрии_10_листов.pdf"

# конкретный эксперимент из research/
python -m isokrus run "02_Изометрии_10_листов.pdf" --experiment exp_03

# ограничить листы и параллельность
python -m isokrus run "02_Изометрии_10_листов.pdf" --pages 1-3 --parallel 4

# сравнить модели на одном и том же промте (meta.json не трогаем)
python -m isokrus run "02_Изометрии_10_листов.pdf" --pages 8 \
  --experiment exp_04 --model gpt-6-luna --reasoning medium
```

Код возврата: `0` — все листы обработаны, `1` — были ошибки, `2` — ошибка
конфигурации или входных данных.

## Команды

| Команда | Что делает |
|---|---|
| `run` | полный цикл: извлечение → LLM → CSV/Excel/разметка |
| `analyze` | вызывает LLM и печатает сырой JSON (отладка промта) |
| `extract` | только рендерит страницы в PNG, без обращений к API |
| `text` | извлечённый из PDF текст с координатами — то, что уходит в промт |
| `dims` | разобранные размеры и отсеянные числа — тоже то, что уходит в промт |
| `experiments` | список экспериментов в `research/` |
| `schema` | strict JSON-схема ответа выбранного эксперимента |
| `prompt` | текст системного или пользовательского промта |

Отдельно живёт `extract_text.py` — тот же доступ к тексту в виде
самостоятельного скрипта: сырой текст, блоки, поиск вхождений, произвольные
единицы координат, а также режим `--prompt`, печатающий ровно тот блок,
который `isokrus` подставляет в системный промт.

```bash
python extract_text.py "02_Изометрии_10_листов.pdf" --pages 8 --prompt
python extract_text.py "02_Изометрии_10_листов.pdf" --coords --units mm


Инструменты разбора размеров лежат в `tests/dimscan` (подсветка на картинке,
эталонные суммы, разведка листа); сам разбор — в `src/isokrus/dimscan.py`,
его зовёт конвейер:

```bash
python tests/dimscan/__main__.py --check      # сверка с эталонными суммами
python tests/dimscan/probe.py 3 --png x.png --crop 130,240,240,285
```

## Текстовый слой PDF

Подписи на изометрии (размеры, номера узлов, координаты привязки) нарисованы
шрифтом, поэтому их положение известно точно — модель оценивала его на глаз и
почти всегда промахивалась. Теперь `extract.py` достаёт подписи тем же
рендером и той же матрицей, что и картинку, и кладёт их в
`PageImage.text_items` в пикселях изображения:

```
24100 [2216,1160,2299,1229] ∠-30
X 78500 [2436,518,2509,555]
```

Блок подписей подставляется в системный промт на место токена `{{PDF_TEXT}}`
(если токена нет — дописывается в конец), а разметка берёт рамки из того же
списка. Модель и картинка смотрят на одни и те же числа, поэтому разойтись
не могут.

## Обрезка пустых полей

Лист печатается на формате шире и выше, чем сама трасса: на
`02_Изометрии_10_листов.pdf` пустое поле занимает 37–53% площади. Vision-модель
всё равно подгоняет картинку под свой лимит входа, поэтому пустое поле не стоит
ничего, а съедает разрешение: на обрезанном листе чертёж получает примерно на
25% больше пикселей на миллиметр, и размерные подписи читаются.

`trim.py` ищет рамку содержимого по факту, никаких заранее заданных полей:

1. берётся уменьшенная копия растра (`Pixmap.copy` + `Pixmap.shrink`);
2. цвет пустого места определяется по левому верхнему углу страницы — белый
   лист и серый скан обрабатываются одинаково;
3. строки и столбцы сканируются от краёв внутрь до первого нарисованного;
   столбцы проверяются только внутри найденных строк, поэтому проверка точная;
4. рамка округляется наружу и расширяется на `TRIM_PAD_PX` белых пикселей.

Порядок в конвейере зафиксирован: **рендер → обрезка → подписи**. Подписи
извлекаются матрицей, уже сдвинутой на срез (`textmap.shifted_matrix`), поэтому
сразу приходят в координатах обрезанной картинки — двигать рамки вручную не
нужно, а значит, нельзя забыть. В модель, в `output/*/pages/*.png` и в разметку
уходит одна и та же обрезанная версия.

Отключается флагом `--no-trim` или `TRIM_MARGINS=0` — нужно, чтобы сравнить
прогоны на полных листах. Параметры: `TRIM_PAD_PX`, `TRIM_NOISE` (запас на
шум бумаги), `TRIM_MIN_INK` (сколько тёмных пикселей считать содержимым),
`TRIM_MIN_RUN`, `TRIM_PROBE_SIDE`, `TRIM_MIN_SIDE`.

Проверить на своих листах, не заходя в API:

```bash
python -m isokrus extract 02_Изометрии_10_листов.pdf --pages 1-10
python -m isokrus extract 02_Изометрии_10_листов.pdf --pages 1-10 --no-trim
```

## Как устроен конвейер

```
PDF ──► dimscan.py ──► размеры          (вектор, в пунктах, до рендера)
  │         │
  │         └──► что на листе является размером
  ▼
render ──► trim.py ──► PageImage(data, text_items, dimensions, в памяти)
                             │
                             ├─ base64 ──► llm.py ──► vision-LLM (JSON)
                             │                ▲
                             │                └── research/exp_NN/
                             │            system.md + {{PDF_TEXT}}
                             │                     + {{DIMENSIONS}}
                             └─► output/exp_NN/pages/*.png  (те же байты)
```

Порядок шагов задан в `extract.py` и не переставляется: **PDF → разбор
размеров по вектору → рендер → обрезка полей → подписи**. Разбор идёт
первым не по скорости: он работает с вектором в пунктах и от обрезки не
зависит, но к моменту рендера уже известно, что на листе является размером.
Рамки размеров пересчитываются в пиксели **обрезанной** картинки той же
матрицей, что и подписи, поэтому промт, разметка и картинка смотрят на одну
и ту же систему координат.

1. **Разбор размеров** (`dimscan.py`). По вектору PDF, до рендера: сначала
   собираются числа листа, потом отсеиваются те, что размером не являются
   (позиционные знаки в квадратах и кругах, координаты привязки `X/Y/Z+`,
   марки труб, номера приборов, штамп), потом к каждому оставшемуся ищется
   ближайшая стрелка или отрезок. Найденное уходит в промт по токену
   `{{DIMENSIONS}}` — вместе со **списком отсеянных чисел**: по картинке
   размер «9» от позиционного знака «9» в квадрате не отличить, и без этого
   списка модель стабильно берёт лишнее в расчёт. Пороги заданы для
   эталонного листа и сами пересчитываются под масштаб каждой страницы по
   кеглю подписей. Выключается `--no-dimscan` или `DIMSCAN=0`.
2. **Извлечение** (`extract.py`). Страницы рендерятся в память, обрезаются по
   пустым полям, кодируются через `Pixmap.tobytes("png")`. На диск до конца
   обработки ничего не пишется. Один объект `PageImage` хранит и байты
   картинки, и base64 для API, и подписи листа, и размеры — сохранённый PNG
   побайтово равен тому, что ушло в модель.
3. **Параллельный анализ** (`pipeline.py`). `ThreadPoolExecutor`, по умолчанию
   до 10 одновременных вызовов (`MAX_PARALLEL`). Ошибка на одном листе не
   роняет прогон — лист помечается в отчёте как `ошибка`.
4. **LLM** (`llm.py`). OpenAI-совместимый API. Режим размышления `high` по
   умолчанию, передаётся через `extra_body={"reasoning": {"effort": ...}}`.
   Формат ответа всегда один: strict `json_schema` — ни промт, ни фолбэк без
   `response_format` не используются, поэтому «что проверяем» и «что требуем»
   не могут разойтись. Повторы (`LLM_MAX_RETRIES` + одна первая попытка):
   сетевой сбой — тот же запрос 1-в-1; ответ есть, но JSON невалиден —
   повтор с возвратом модели её ответа и текста ошибки. Причины повторов
   пишутся в `stats.json` полем `retry_reasons` (пустой `content`, не-JSON,
   не по схеме, сетевая ошибка): лечатся они по-разному, а по счётчику
   повторов неразличимы.
5. **Отчёты** (`report.py`). Суммирование длин делает программа, не модель.
   В иерархической схеме (`exp_04`) складываются только корневые
   `parent_length`: дочерние участки уже сидят внутри родительских, и сложение
   всего вместе посчитало бы одни и те же миллиметры дважды. Если заявленная
   моделью сумма разошлась с программной, в колонку «Статус» попадает
   `расхождение N мм`, а в «Замечания» — оба числа.
6. **Разметка** (`annotate.py`). Числа, названные моделью, сопоставляются с
   подписями листа и обводятся по их настоящим рамкам: синий — обобщённая
   длина, зелёный — дочерний участок, оранжевый — рамка по `bbox` модели
   (используется, только если у листа нет текстового слоя). В шапке листа
   пишется, сколько чисел размечено и сколько на листе не нашлось.

## Эксперименты с промтом и схемой ответа

Каждая папка в `research/` — отдельная версия промта и структуры ответа.
Имя папки = номер эксперимента.

```
research/
  exp_01/
    meta.json        # модель, reasoning_effort, описание (необязательно)
    system.md        # системный промт
    user.md          # текст пользовательской инструкции (необязательно)
    response.json    # JSON Schema ответа
```

Чтобы завести новую версию — скопируйте существующую папку и переименуйте
(`exp_05`), поправьте `system.md` и `response.json`. Код менять не нужно:

```bash
python -m isokrus run file.pdf --experiment exp_05
```

В `system.md` можно оставить токен `{{PDF_TEXT}}` — на его место подставится
блок подписей листа с координатами. Отключается это в `meta.json` ключом
`"pdf_text": false`.

Два токена означают два независимых блока данных, и выключаются они
независимо: `"pdf_text": false` убирает подписи, `"dimensions": false` — разбор
размеров. Пустой блок размеров при включённом разборе намеренно остаётся в
промте со словами «размеров не найдено, это дефект разбора» — чтобы модель
сообщила о поломке, а не молча выдумала числа. А вот при выключенном разборе
раздел убирается целиком: сообщать о дефекте, которого не было, хуже, чем
не сказать ничего.

Ответ описывается обычной JSON Schema, которая на лету конвертируется в
pydantic-модель (`schema.py`): поддерживаются `$defs`/`$ref`, `enum`,
`anyOf` с `null`, `type: ["number", "null"]`, вложенные объекты и массивы.
Принимается и обёртка `response_format` от OpenAI
(`{"name": ..., "strict": true, "schema": {...}}`) — она просто распаковывается.
Эта же схема уходит в API как `json_schema` со `strict: true`, так что
контракт ровно один — расхождение между «что проверяем» и «что требуем»
невозможно.

Модель и режим размышления задаются на уровне эксперимента (`meta.json`),
глобальные значения — в `.env`. Для сравнения «та же модель против этой на
том же промте» есть флаги: они перекрывают `meta.json`, не трогая папку
эксперимента, и фактическая модель пишется в `stats.json`.

```bash
python -m isokrus run "02_Изометрии_10_листов.pdf" --pages 8 \
  --experiment exp_04 --model gpt-6-luna --reasoning medium
```

`meta.json` — зафиксированная версия опыта, поэтому его правильнее не
переписывать под каждый прогон: иначе через месяц не вспомнить, каким
составом считалось.

### Что в готовых экспериментах

| Эксперимент | Идея | Схема ответа |
|---|---|---|
| `exp_01` | базовый разбор: размеры, признак «вошло/не вошло», bbox для разметки, явный разбор исключений | `segments[]` + `excluded_dimensions[]` + bbox |
| `exp_02` | облегчённый: плоский список чисел, без bbox и разбора исключений | `dimensions[]` |
| `exp_03` | трактовка через маршрут: границы `start/end_point`, обход с индексами, блок самопроверки суммы | `segments[]` + `start_point`/`end_point` + `verification` |
| `exp_04` | иерархия трассы: магистральные ветви, обобщённая длина и вложенные участки; итог складывает программа | `branches[]` + `parent_length`/`child_segments` |
| `exp_05` | выбор размеров по меткам: модель отвечает, какие из найденных размеров входят в длину, а какие вложены; числа не пишет, сумму считает программа | `included[]` + `excluded[{index,reason}]` |

Блок разобранных размеров подключается токеном `{{DIMENSIONS}}`
в `system.md` любого эксперимента; если токена нет, блок дописывается в конец промта,
как и блок `{{PDF_TEXT}}`. Выключается в `meta.json` ключом
`"dimensions": false` либо флагом `--no-dimscan`.

#### Подсветка на листе (`overlay.py`)

По умолчанию в модель уходит не снимок листа, а тот же снимок с пометками:

* вокруг **уже нарисованного** числа обведена тонкая зелёная рамка — своё
  значение туда не вписывается;
* на её верхнем правом углу сидит зелёная плашка с меткой размера и белым
  номером: перекрывает рамку, а не стоит рядом, потому что рядом с числом на
  чертеже обычно чужая выносная линия;
* размерная линия подсвечена и отступлена от концов, чтобы исходные
  наконечники остались видны; наконечники дорисованы затемнённым тоном того
  же цвета. Выноска (одна стрелка) рисуется синим, отрезок (две стрелки) —
  малиновым.

Зачем: модель читает числа с картинки неверно — на пяти листах из десяти и
`glm-5.3-flash`, и `gpt-6-luna` независимо писали «22100» вместо `24100`, и
промах уезжает прямо в сумму. Отключается `--no-overlay` или
`DIMSCAN_OVERLAY=0`. На диск всегда кладётся исходный снимок: подсветка нужна
модели, а человеку для сверки — настоящая выдача с чертежа.

#### Зачистка листа (`clean.py`)

Шаг предобработки между разбором размеров и отправкой листа в модель: с
картинки закрашивается то, что размером не является. Модель получает лист и
список размеров одновременно, и всё, что на картинке похоже на размер, тянет
её в расчёт — на девятом листе верны все пять размеров, но рядом лежат
квадраты с «1» и «2», и модель их тоже видит.

Что закрашивается (фильтры включаются поимённо через `DIMSCAN_CLEAN_FILTERS`):

| фильтр | что стирает |
| --- | --- |
| `signs` | знак в квадрате: номер узла или позиционное обозначение |
| `notes` | опорный знак «О3», «4/3» и примечание в рамке |
| `leaders` | выноска знака — линия, уходящая из его рамки |
| `rejected` | число, которое разбор отверг как размер: координаты привязки, номера листов |

Зачем стирать вместе со знаком и выноску: если убрать только знак, на листе
остаётся стрелка без подписи, а стрелка от знака и стрелка от размера на
картинке неразличимы.

**Чего фильтры не делают и почему.** Отличить данные привязки от размеров по
геометрии текста нельзя: зазор между префиксом и числом не является признаком.
На всех десяти листах встречаются `Z+ 10695` в 5 px (мусор) и `Z+ 1900` в 55 px
(размер), `DN50X50 174` в 75 px (размер) и `DN50X50 2` в −105 px (мусор).
Поэтому единственное правило отсева — «это число разбор уже отверг», оно
проверяемо: иначе число было бы в списке размеров, а эталонная сумма
достигается подмножеством именно принятых чисел.

По той же причине выноска отбирается отрицанием: отрезок у знака, который не
совпадает ни с одной размерной линией. Отбор по толщине не годится — у всех
отрезков у знака на восьмом листе толщина 0.72 pt, но такую же имеют ещё 689
отрезков листа; отбор по длине тоже не годится — у знаков встречаются и 33 px,
и 292 px, и обе полосы накрывают настоящие размерные линии.

Последний рубеж: область, под которую попал центр подписи размера, не
закрашивается вовсе. На всех десяти листах под проверкой не осталось ни одного
задетого размера; такие случаи видно в `meta` листа как `clean.kept`.

Включается `--clean` или `DIMSCAN_CLEAN=1`. На диск всегда кладётся исходный
снимок: зачистка нужна модели, а человеку для сверки — настоящая выдача.

#### Ответ по меткам (`exp_05`)

Каждому размеру в блоке присвоена метка `P1`, `P7` и т. д. Это не украшение:
на листе 9 есть два размера по 123, на листе 10 — по два 220, 244, 341 и 134,
и списком значений их не различить.

Ответ по меткам (`included` / `excluded`) разворачивается в числа программно
(`indices.py`), после чего считается сумма, строится формула и работает
разметка. Модель при этом физически не может назвать число, которого на
листе нет, — она выбирает из списка. Метки, которых на листе нет, попадают в
«Замечания», а не теряются молча.

**Метка, о которой модель не сказала ничего, считается включённой.** Ответ
читается как список исключений, а не как список участков, и молча выбрасывать
размер, который модель просто не упомянула, — это терять на десятом листе
2450 мм. На прогоне с зачисткой модель вернула 14 меток из 15, `P7` не попала
ни туда, ни сюда, и весь лист разошёлся ровно на эту величину при верно
выбранных остальных четырнадцати. Такие метки перечисляются в ответе как
`unclassified_marks`, а их участки помечены `"unclassified": true`.

Такая форма выросла из прогона `exp_04` по всем десяти листам: поле
`parent_length` не могло отличить размер, нарисованный на листе, от суммы
нескольких отрезков, и модели склеивали `900 + 200` в «1100», а на листах,
где из листа надо выбросить вложенные размеры, та же склейка считала их
дважды.

## Конфигурация

Все параметры — из окружения, см. `.env.example`. Ключевые:

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `LLM_API_KEY` | — | ключ (обязателен) |
| `LLM_BASE_URL` | `https://api.dslab.tech/v1` | endpoint; также читается `OPENROUTER_BASE_URL` |
| `LLM_MODEL` | `glm-5.3-flash` | модель |
| `LLM_REASONING_EFFORT` | `high` | режим размышления |
| `MAX_PARALLEL` | `10` | одновременных вызовов LLM |
| `RENDER_DPI` | `320` | плотность рендера |
| `MAX_IMAGE_SIDE` | `4096` | ограничение по большей стороне, px |
| `TRIM_MARGINS` | `1` | обрезать пустые поля листа ( `--no-trim` отключает) |
| `TRIM_PAD_PX` | `12` | белый запас вокруг среза, px |
| `TRIM_NOISE` | `8` | на сколько уровней темнее фона пиксель считается нарисованным |
| `TRIM_MIN_INK` | `1` | сколько тёмных пикселей в строке/столбце считать содержимым |
| `EXTRACT_PDF_TEXT` | `1` | доставать подписи из PDF и подставлять их в промт |
| `PDF_TEXT_MIN_HEIGHT_PX` | `0` | отсечь подписи мельче указанной высоты шрифта |
| `PDF_TEXT_MAX_ITEMS` | `0` | лимит подписей на лист в промте, `0` = без лимита |
| `DIMSCAN` | `1` | искать размеры по вектору и подставлять их в промт (`--no-dimscan` отключает) |
| `DIMSCAN_MIN_LENGTH` | `12.0` | минимальная длина размерной линии, в пунктах эталонного листа (порог сам пересчитывается под масштаб страницы) |
| `DIMSCAN_REJECTED` | `1` | передавать ли модели список чисел, отсеянных как «не размер» |
| `DIMSCAN_OVERLAY` | `0` | рисовать на листе пометки размеров и отправлять в модель подсвеченный снимок (`--overlay` включает, по замерам точность ниже) |
| `DIMSCAN_CLEAN` | `0` | закрашивать на снимке знаки в квадратах, опорные знаки, выноски и отвергнутые числа (`--clean` включает) |
| `DIMSCAN_CLEAN_FILTERS` | `signs,leaders,notes,rejected` | какие зачистки применять; работает только вместе с `DIMSCAN` |
| `ANNOTATE_COORD_SPACE` | `norm1000` | система координат `bbox` модели: `norm1000` или `px` |
| `LLM_PRICING_INPUT` / `_OUTPUT` | `0` | тарифы за 1M токенов для расчёта стоимости |
| `LLM_PRICING_REASONING` | `0` | тариф за 1M токенов рассуждения; `0` = как у output |
| `LLM_PRICING_CACHE_WRITE` / `_READ` | `0` | тарифы за запись в кеш и за чтение из него |
| `LLM_PRICING_TABLE` | — | тарифы по моделям (JSON), см. ниже |

Тарифы по моделям нужны, потому что модель переключается флагом `--model`, а
цены разные: с общими настройками прогон по дорогой модели молча считался по
тарифу дешёвой. Если таблица задана, а модели в ней нет и нет ключа
`default`, стоимость помечается как неизвестная (`cost_known: false`), а не
подставляется чужая.

```
LLM_PRICING_TABLE={"gpt-6-luna": {"input": 10, "output": 50, "reasoning": 50, "cache_write": 12.5}, "default": {"input": 7.5, "output": 25}}
```

Про кеш: `prompt_tokens` у провайдера **включает** и запись в кеш, и чтение
из него (проверено запросом: 2358 = 2355 кеш + 3 служебных, при повторе
`cached_tokens` растёт, а `prompt_tokens` не меняется). Поэтому обычный вход
считается как `prompt` минус кеш, иначе эти токены оплачиваются дважды.
Разложение видно в `stats.json`: `cache_write_tokens`, `cache_read_tokens` и
соответствующие `cost_*`.

## Ограничения

- Суммирование выполняется программой по длинам, которые вернула модель;
  правильность самих чисел на чертеже проверяется только человеком.
- Координаты разметки точные, но берутся из текстового слоя PDF. Если чертёж
  пришёл сканом без встроенного текста, подписей не будет: разметка
  вернётся к оценке модели и станет заметно грубее, а шапка листа об этом
  предупредит.
- Число, которого нет в текстовом слое, не размечается. Это осознанно:
  придумывать рамку значило бы рисовать правдоподобную, но неверную
  картинку. Такие значения перечисляются в шапке листа.
- Одноимённые размеры раздаются подписям по порядку ответа модели. Если она
  перечисляет ветви в другом порядке, чем идёт чтение листа, рамки могут
  переехать между соседними участками — это видно по номерам в плашках.
- Размеры вида «960 + <12» требуют подсчёта повторов отступов — это самая
  частая причина `confidence: medium`.
- Блок `03_Пример_расчета_длины.pdf` используется как эталон разметки и в
  расчёт не входит.
